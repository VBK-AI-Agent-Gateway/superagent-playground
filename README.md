# CRM 客户关系管理系统

面向中小销售团队的轻量 CRM：客户档案、线索转化、商机看板、跟进提醒与数据备份，全部在浏览器内运行。

**零依赖、零构建**：只用原生 HTML / CSS / ES Module，直接打开 `index.html` 即可使用，无需 npm、打包器或后端服务。所有数据保存在浏览器 `localStorage`，不上传任何服务器。

## 快速开始

### 方式一：本地静态服务器（推荐）

```bash
cd crm-sales-app-1603499d3430
python3 -m http.server 8000
# 浏览器访问 http://localhost:8000
```

### 方式二：直接打开

双击 `index.html`（或拖进浏览器）即可。注意部分浏览器在 `file://` 协议下会限制 ES Module 加载，若页面空白请改用方式一。

### 方式三：部署到 GitHub Pages

1. 把本目录内容推送到仓库（例如 `main` 分支的根目录或 `docs/` 目录）；
2. 打开仓库 **Settings → Pages**，Source 选择对应分支与目录；
3. 等待发布完成后访问 `https://<用户名>.github.io/<仓库名>/`。

无需任何构建步骤，Pages 直接托管静态文件即可。

## 功能一览

| 模块 | 说明 |
| --- | --- |
| 仪表盘 | 客户总数、商机总额、进行中商机、赢单金额、线索待转化、跟进记录数；商机阶段分布与客户状态分布（纯 CSS 条形图）；即将到来的跟进提醒（逾期高亮）。 |
| 客户管理 | 列表支持关键词搜索、状态/来源筛选、多字段排序、分页；新建 / 编辑 / 删除客户，删除时级联清理联系人、商机与跟进记录。 |
| 客户详情 | 基本信息与概览、联系人列表、该客户的商机列表、跟进记录时间线（含下次跟进日期）。 |
| 线索管理 | 线索录入与维护，一键转化为客户档案，可选同时创建商机并指定初始阶段。 |
| 商机看板 | 六阶段看板（初步接触 / 需求确认 / 报价 / 谈判 / 赢单 / 输单），支持拖拽换列与「上一阶段 / 下一阶段」按钮，列内显示数量与金额小计。 |
| 跟进记录 | 记录跟进时间、方式、内容与下次跟进日期；归属对象可以是客户或商机；支持按方式、范围（含「已逾期」）筛选与分页。 |
| 数据管理 | JSON 导出备份、复制到剪贴板、导入（覆盖 / 合并两种模式）、清空数据、恢复演示数据、最近操作记录。 |

## 架构说明

- **数据与视图分离**：所有读写都经过 `js/data/store.js` 的 `store` 对象；视图文件只导出渲染函数，返回 HTML 字符串，不直接绑定事件。
- **统一数据接口**：`store.createCustomer`、`store.moveDealStage`、`store.importJson` 等修改方法内部统一走 `commit(reason, mutate)`，完成「变更 → 写 localStorage → 通知订阅者」三步，并把操作写入变更日志。
- **事件委托**：`js/app.js` 在 `document` 与视图根节点上统一监听，按 `data-action` / `data-sort` / `data-page` / `data-filter` 分发，视图重绘后无需重新绑定事件。
- **hash 路由**：`#/dashboard`、`#/customers`、`#/customers/<id>`、`#/leads`、`#/deals`、`#/activities`、`#/data`，刷新与前进后退都能正确还原视图。
- **数据格式**：导出文件为 `{ version, customers, contacts, leads, deals, activities, changes, meta }` 的 JSON；导入时 `replace` 覆盖全部数据，`merge` 保留现有数据并在重新映射 id 后追加。

## 交互提示

- 看板卡片可拖拽到目标阶段列，也可用卡片上的箭头按钮逐级流转。
- 按 `Esc` 关闭当前弹窗；移动端用页头左侧按钮展开/收起导航。
- 搜索框输入时保持焦点，列表延迟刷新，不会打断连续输入。

## 数据安全

数据仅存于当前浏览器。清除浏览器站点数据、更换浏览器或更换设备都会导致数据不可见，请定期在「数据管理」中导出 JSON 备份。
